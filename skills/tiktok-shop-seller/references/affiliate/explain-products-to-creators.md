# Explain products to creators

Goal: turn approved product evidence into a useful creator answer or content brief.

1. Identify the creator's actual question and the exact shop/product/variant.
   Fetch the current product via the available product tool; use
   `affiliate_get_product` when its enriched context is helpful.
2. Use published [Product Knowledge](../product-management/manage-product-knowledge.md) for usage instructions,
   Q&A and creative cases. Read only relevant local original manuals, approved FAQ
   evidence or historical videos/notes. Apply
   [knowledge ownership](../foundations/workspace-and-data-ownership.md).
3. Separate current listing facts from supplementary usage advice and creative ideas.
   Do not treat stale video pricing or an old viral claim as today's product truth.
   Explain uncertainty where evidence is missing; ask rather than invent claims.
4. Build a short, audience-appropriate explanation: benefit supported by evidence,
   how to use/demo, key limitations, and a few optional creative angles. Historical
   success is inspiration, not a guarantee of future sales.
5. If asked only for a brief, keep it as a draft. If asked to reply, use the
   [creator message workflow](handle-creator-conversations.md) and verify delivery.
   Do not upload arbitrary local files unless the current tool supports it and
   the merchant authorized that material.

New reusable insights may become a local knowledge draft if requested. Publishing
to cloud Product Knowledge is a separate explicit step, not a side effect of replying.
Never copy a creator's private message into a public knowledge source.
