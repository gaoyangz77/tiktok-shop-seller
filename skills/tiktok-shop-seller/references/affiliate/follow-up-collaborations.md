# Follow up existing collaborations

Goal: move an existing relationship forward based on actual obligations and recent
activity, not on a generic follow-up timer.

1. Read backend work items without dispatch and inspect the relationship timeline,
   relevant collaboration and sample state.
2. Determine the next unmet obligation and whether a reply, sample action, product
   explanation or commercial change is actually needed. Check the latest outbound
   activity and creator preferences to prevent duplicate or unwanted contacts.
3. For a missing sample use [delivery exceptions](../order-management/resolve-delivery-exceptions.md).
   For product education use [explain products](explain-products-to-creators.md).
   Neither workflow implies permission to reship or change commission.
4. Execute a supported work-item action through
   [creator conversations](handle-creator-conversations.md). For an explicit
   direct contact, select the verified channel and stable message key.
5. Change collaboration terms or creator contact information only when explicitly
   requested and verified. A suggested email in a message is not authorization to
   silently replace the stored contact route.

Verify the action's actual status. State remaining commitments and blockers.
Do not keep a parallel relationship database or start recurring outreach unless
the merchant separately asks for supported scheduling.
