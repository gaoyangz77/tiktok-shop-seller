# Handle complaints and review-related recovery

Goal: resolve the buyer's underlying problem, not merely change a rating.

1. Read the current conversation and related order/item; distinguish product
   usage difficulty, damaged/missing item, late delivery, and a refund dispute.
   A bad-review inbox signal is a lead, not proof of the buyer's current issue.
2. Read merchant-approved remedies and relevant usage evidence. For delivery
   investigations use [delivery exceptions](../order-management/resolve-delivery-exceptions.md);
   for money/returns use [returns and refunds](../order-management/process-returns-and-refunds.md).
3. Propose the supported remedy within authorization. If evidence or authority is
   missing, ask a specific question. Do not promise replacement stock, delivery
   dates or compensation without confirming them.
4. Follow [triage and reply](triage-and-reply.md) to send and verify. Do not condition
   support/refunds on review removal or write a review on the buyer's behalf.
5. If a backend recovery process is already active, inspect available state before
   adding another contact. Do not create a duplicate local outreach loop.

Completion means the authorized reply/remedy has a verified status. A courteous
reply is not proof the buyer's issue is resolved. Keep only reusable, approved
product-learning notes if requested; never copy the buyer's private transcript
into product FAQs.
